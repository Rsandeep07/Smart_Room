Six things that will actually cost you time                                                                                                    
1. Windows Firewall blocks inbound port 8080 by default. The ESP32 will fail silently and you'll blame the firmware. This is the single biggesttime sink — fix it first:
New-NetFirewallRule -DisplayName "Smart Room backend" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow                           1. (needs an admin terminal)
2. Producers must use your PC's LAN IP, not localhost. localhost on the ESP32 means the ESP32 itself. Get it with ipconfig.                    3. ventTemperature is not optional. Your hardware teammatethe AC supply vent, not just the DHT22. Without it, ACstatus never transitions, runtime never accumulates, and the cold-room alert can never fire — which is half the project. This is easy to overlobecause the DHT22 feels like "the temperature sensor."
4. Both producers must send the identical roomId. A typo gives you two rooms, each with half the data, and a dashboard showing — for the other half.
5. Give the ESP32 a DHCP reservation or static IP, or the camera URL changes on every reboot.                                                  6. Keep the simulator. It's your diagnostic: if the real pimulator and see whether the backend still works. Thattells you instantly whether the bug is yours or theirs.
